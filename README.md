# 云听 YUNTING

> 一个**伪装成听觉服务公司官网**的网页解谜 / ARG。
> 纯静态（HTML + CSS + 原生 JS），零外部依赖、零音频文件（所有声音由 Web Audio 实时合成）。

**线上：<https://muc260.github.io/yunting/>**
**仓库：<https://github.com/MUC260/yunting>**

> 虚构作品：云听科技、秦河县、所有人物与工单均为虚构，与任何真实机构、企业无关。

---

## 一、它是什么

打开它是一个正经的行业网站：**云听**，2026 年的听觉科技公司，两条业务线——
**云听·验配**（助听器验配）和 **云听·代祭**（代客祭扫）。

首页有一条否认过度的公告：

> 近期有用户反馈，代祭录音中会出现非现场声音（人声呼唤、敲门、念名字等）。
> 经技术核查，录音均由现场设备采集，未做任何后期处理。
> 如遇上述情况，请照常勾选「已送达」，不要中断工单。

你点「免费在线听力自测」，做八组音。**第八组的频率是 20 Hz——低于人耳下限。你还是按了「听到了」。**

```
标定完成 · 听道编号 A-037
您已加入云听·代祭 志愿听道名录，可承接代祭试听任务。
```

从那以后，平台开始给你派单：替家属去墓前上香、焚化、念祭文，顺便"听一听那边有没有动静"。

## 二、12 单 = 12 种动作

**每一单的玩法都不一样，全篇只有第 7 单需要打字。**

| 单 | 名称 | 你要做的事 | 难度 |
|---|---|---|---|
| 01 | 香烛 | 点开三个开关（电源／电量／左右耳） | 入门 |
| 02 | 验配 | 把四条频段线接到耳廓图对应点位 | 入门 |
| 03 | 屏息 | 开始后二十秒内不许点、不许按键 | 入门 |
| 04 | 侧碑 | 把取景框拖窄，碑侧被挡住的一列字才露出来 | 普通 |
| 05 | 对频 | 把写着校正值的那一行滚到红色基准线上 | 普通 |
| 06 | 增益 | 按住不放推增益，让指针停进绿区（会啸叫） | 普通 |
| 07 | 祭文 | 写一段祭文——**不许复述逝者原话** | 普通 |
| 08 | 引路 | 一笔画完一个符 | 普通 |
| 09 | 代守 | 必须离开页面六十秒（或点"闭眼"守十五秒） | 困难 |
| 10 | 正名 | 碑上名字刻错了。这一页的字，其实你可以改（F12） | 困难 |
| 11 | 双端 | 另开一个标签页，把六位口令填进去对时 | 困难 |
| 12 | 不听 | 公司让你别听。你要不要摘下耳机 | 终局 |

**脊柱**：每单归档后，听力档案里多一段 0.5 秒波形。十二段连起来播放，是**摩斯电码**——

> **D O N O T L I S T E N**

而《听道守则》写着：不得摘下耳机、不得调低音量、遇异常照常完成。

**双结局**：摘下耳机 → 听道注销，8 kHz 以上频段被回收，此后那个频率你按"听到了"，系统回"未检测到"。
继续听 → 你成为在线听道 1,249 条之一，待办任务一单，收件人是你。

## 三、文件结构

```
index.html          外壳（页头/导航/页脚 + 挂载点）
css/yt.css          全部样式（医疗蓝白 + 工单系统灰）
js/data.js          由 content/*.json 生成的注入数据（勿手改）
js/yt.js            框架：存档、分级提示、Web Audio 合成、摩斯、波形、元恐怖
js/chapters.js      12 章交互模块（每章一个独立动作）
js/app.js           hash 路由 + 伪装层渲染 + 工作台 + 工单页 + 结局
content/orders.json 12 张工单的源数据（改稿底本）
content/site.json   10 个网站页面 + 5 条公告的源数据
tools/gen_data.py   把 content/*.json 编译成 js/data.js
tools/deploy-yunting.ps1  通过 GitHub API 发布到 Pages
```

**改文案的流程**：改 `content/*.json` → 跑 `python tools/gen_data.py` → 部署。

## 五、已知限制

| # | 限制 |
|---|---|
| 1 | **必须联网**才能玩（部署在 GitHub Pages），本地 `file://` 也能开，但 hash 路由与音频在部分浏览器受限 |
| 2 | 6 章依赖声音；没有做"完全无声通关"的视觉替代（只有第 3、9 章有降级） |
| 3 | 第 10 章要求玩家会按 F12；不会的话可以连点五次碑上的错字跳过 |
| 4 | 第 11 章要求开两个标签页；手机上体验较差 |
| 5 | 目前没有配图（工单扫描件、墓区平面图、听力图都是文字/CSS 画的） |
| 6 | 进度存在 localStorage，换浏览器/清缓存会丢 |

## 六、设计依据（为什么这么做）

这一版不是拍脑袋做的，是先做了四项数据调研再定的：

1. **题材谱系**：抓了「谜页集」108 部作品的元数据，按恐怖来源分 14 类。殡葬服务链**零覆盖**、以"听"承担判断只有 4 部且没人让玩家真用耳朵做题——这两个蓝海就是本作的位置。
2. **结构模板**：拆了 7 部开源作品的仓库（67 页/1.3 万行/0 音频文件是头部作品的常态；Top10 完成率均值只有 2.09%）。
3. **现实结合**：grep 了 7 部作品的源码，**外部链接 0、tel 0、真实搜索引擎 0**——"去真实地图搜某地"这类外部求证在同类作品里是 0/7，因为它不可判定、且会失效。所以本作全部用"站内可验证 + 浏览器原生 + 你的真实数据"。
4. **交互机制**：统计了 45 种动作，避开红海（翻页 11 部、档案检索 9 部、输密码 7 部），12 章里有 8 章用的是全库没人用过的动作。
